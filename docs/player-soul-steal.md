# Selected playable Soul Steal

The native checkpoint now accepts the original Soul Steal command: Back, Forward,
Down-forward, Down, Down-back, Back, Forward, then either hand attack. Directions
use the facing captured at the first input. The private spell definition charges
50 MP, including an exact-cost cast, and successful casting learns spell five.
Ordinary starts retain their existing 20 MP maximum; this feature grants nothing.

The actual player owner runs original state37, animationDA, voice, shield removal,
use timer12, status and invincibility, then normal recovery. At pose seven with one
animation tick remaining, it requests the six original profile22 outlines and
blueprint112 in original order. The shared runtime owns the real factory and its
child53 in slot47, which shares capacity with Echo of Bat. A failed optional request
creates no attack or substitute slot and consumes no spell-initialization RNG.
The original global flash uses profile12. Rendering never advances these owners.

The attack reads private spell-five INT/RNG/Mojo metadata and shares the original
7..10 enemy cooldown groups across generations. Its original hitbox-state80 bit
selects active-screen targets without an AABB distance test; no giant synthetic
hitbox substitutes for that rule. Original target masks, screen bounds, slot order
and cooldown still apply. The stage creates actual [healing orbs](soul-steal-orbs.md)
in slots96..127 after contact selection and before damage/immunity processing,
including infinite-HP targets. Exhausted actor capacity omits the orb while retaining
the hit and unrelated owners. Actual damage/death/EXP use the native enemy services.
The orbs render private artwork, home into Alucard and feed the existing deferred
healing owner; they do not heal immediately at attack time.

Captured effect origins rebase without extra updates. Menus hold player simulation,
resources and actual effect owners. This spell does not request spirit scene freeze.
Full stage initialization/Continue clears transient casting/factory state. Learning
uses the existing version-nine field; no save migration or default grant changes.

Public authored tests cover both command facings, exact/insufficient MP, disabled
availability, pose timing, status/recovery, one-shot origins, real slot/group
ownership, row exhaustion, occupied slot47, malformed metadata rollback, global
contacts, immune/infinite-HP targets, active-screen bounds, cooldown and exhausted
orb capacity. Component tests do not substitute for native gameplay evidence.

A private comparison executes the original US factory updater, child53, spell
initialization and group recount for 64 supplied contexts and2,560 updates, including
facing, INT/Mojo, RNG and freeze/retirement. Debug and ASan/UBSan native traces match
byte for byte and match the original instructions. Equipment-count, random-number
and destruction boundaries use explicit adapters. It supplies player state rather
than proving ordinary casting or stage hit detection.

Separate muted native LLDB checks use actual commands/rendering, original50MP,
learning, one pose-seven trigger, actual outline children, global attack, enemy
damage/death/kill credit, five homing orbs/contacts, healing and recovery. Explicit
room/position/HP50/MP50/contact-protection fixtures make these focused checks,
not ordinary acquisition or uninterrupted-route evidence. A separate in-memory v9
transfer checks retained learning and fresh transient state; ordinary save files
are never written. Full shared contention, raster/audio timing, water/equipment/
familiars, whole-route and console parity remain incomplete. Alucard and the castle
are not complete.
