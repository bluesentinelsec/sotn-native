# Shared Hellfire runtime

The selected shared player runtime now owns original Hellfire factories and
children 24..29 alongside existing player effects. It advances real private
animations, borrows real stage rows, initializes spell-two attacks/groups and
connects those attacks to native enemy damage. Native Hellfire controls remain
disabled until the actual player casting/MP/learning, gradient uploads, palette
visibility and sprite rendering owners connect. An upload intent is not completed
texture data. This is not playable-Hellfire or Alucard completeness.

The player boundary can reserve an actual root33/circle37 or original finishing
flash factory and receive its real outcome. Eight occupied factory slots return
false availability without inventing a child. Factories advance before children;
requests created by a child wait until the following factory pass. Actual original
slot selection, full parameters and source metadata stay with the existing owner.

Beam, circle and flash reserve one actual stage row each. Exhaustion retires the
child, including the beam/flash FFFF signal, without substitute storage. Circle
continues after casting; beam/flash stop when casting ends. Stage commit and the
runtime share child/role/phase/row/group validation, preserve unrelated leases
and release retired rows. Entry rebases retained positions/packets without ticking
animations or producing factory/sound/upload events.

Root and flash entity priority is 448; a circle's row priority does not replace
its entity priority. Fireballs retain their actual priority when creating trails.
Large fireballs request trails from the position **before** movement. Their even
clock RNG call still occurs if optional factory capacity is exhausted; a trail
consumes its separate birth RNG only after a real child allocates.

All three private animation streams run after the original controller. Normal
fireballs loop; large fireballs reach their actual launch pose and later loop;
trails retain terminal duration until the next controller retires them. Invalid
bounds, durations or loop targets fail transactionally. No launch-delay timer
replaces animation. Original signed positions/fractions and visual metadata remain
with their actual children.

Spell two uses actual private INT/equipment/RNG metadata and the least-used original
group for its actual slot range. Counts are retained through births and recounted
after updates; Wolf's forced replacement preserves the original slot31 survivor.
Native hit feedback retires normal fireballs on their next update; large fireballs
continue piercing under the shared enemy cooldown. Shared-runtime failures preserve
the runtime and character RNG. The frozen dispatcher holds children that lack the
original flag10000, without advancing their animation or factories improperly.

Public authored schedules/timelines cover normal/large lifetimes, source priorities,
pre-movement trail origins, capacity failure, retained rows, frozen updates, no-tick
entry, stale contact feedback and malformed-animation rollback. Existing spirit
and Wing Smash tests remain enabled.

Private comparisons match 16 supplied facing/Up/interruption/freeze contexts,
3,840 ordered original updates and 3,055 actual child snapshots. Original factories,
controllers, private animations, spell initialization, RNG and group recount execute;
allocators, destruction, equipment count, sound and GPU upload use explicit boundary
adapters. Debug and ASan/UBSan snapshots match. These supplied player states are not
an ordinary spell command, acquisition, camera route or console replay.

Separate native room-three checks use actual stage row commits, ordinary character
INT/enemies and real normal/large projectile contacts and damage. They use an explicit
room start, X124/contact protection and supplied casting state. They do not establish
actual commands/MP/learning, gradient pixels, rendering, an uninterrupted encounter
or full-game parity. No user save slot is written. Private inputs/traces remain local;
ordinary starts and version-nine saves stay unchanged.
