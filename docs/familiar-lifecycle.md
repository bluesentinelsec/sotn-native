# Selected familiar loading and retirement

The native lifecycle now owns verified US Fairy loading, cached reselection,
deselection and atomic four-slot retirement through an owned load-boundary API.
Ordinary relic-menu activation remains disabled until saved progression, remaining
audio/cutscene lifecycle, whole-pass transactions and
integrated acceptance are complete. Existing grants, pools and v9 saves are unchanged.

`SotnLaboratory_SelectFamiliar` accepts original0/3 in an actual idle menu/load
context and requires the found private Fairy card. It validates actual player,
control, card/progression and full row ownership before loading. First selection
opens all four verified resources and prepares detached graphics/SPU candidates,
and root/wings. The common CD owner is already initialized by native bootstrap.
Its prepared sound dependency is checked without changing the live binding, then
rebound before the old SPU is retired. Current/saved/in-flight decoders, resampler/
ADPCM positions and both CD queues retain the same actual owner without a tick.
Allocations, file reads and metadata validation finish before actual retirement
and ownership publication. No detached candidate supplies gameplay readiness
before the actual transaction commits.

Graphics preparation retains resident pixels, validity, capture/cache and palette
jobs, then uploads familiar data only in the candidate. Sound preparation retains
RAM, voices, predictors, scripts, SEQ and queued commands before loading bank2 in
its candidate. Failure preserves live owners; unused candidates are destroyed.
An active render target cannot be replaced. The single committed renderer/SPU/CD
owners continue through the actual native callbacks after pointer replacement.

Same-selection initialization preserves root generation and load count. Changed
selection increments loads once; cached reselection reuses the actual resources,
renderer, SPU and CD owner. Deselecting clears only real familiar entities/rows,
retaining loaded artwork/audio, overlay history and queued/playing audio. It does
not heal, grant a card, tick a clock or release FFF. Player initialization and normal
callbacks now share the same full actual player/status/contact/velocity snapshot.

Ordinary connected-room entry now binds actual retirement and displacement. It validates
the complete familiar namespace before changing player/stage ownership, then retires
non20000 familiar entities and their real rows before the destination stage pass.
Retained root/wings use the actual old-minus-new player screen position, including
fractions. Destination initialization applies only subsequent camera movement, avoiding
a duplicate camera shift. No familiar callback, initializer, load count, event timer,
history or RNG advances during entry. Original Engine_3 does not call ServantInit;
engine mode2 belongs to its separate special-return context.

Both native builds exercise actual adjacent Laboratory rooms with an owned-initialized
Fairy and real Potion producer:33 temporary rows retire, initialized medicine survives
and completes deferred HP5-to55, and retained Fairy rendering contributes29 pixels.
A second crossing through full Step invokes each4..7 callback once, advances one
player/game frame, and preserves familiar progression. Orphan rejection precedes player/
stage mutation; real menu and draw checks retain their holds. The prior-head native
regression fails this early rejection check. Supplied card/item/health/protection and
edge/camera/fraction fixtures are separate from ordinary acquisition or uninterrupted
route evidence; destination actors and whole-pass rollback retain their existing limits.

Full native engine initialization now derives selection from the actual active private
card definition and binds original mode0 after player/stage bootstrap and AluInit's64
RNG calls. It prepares the actual four resources and renderer/SPU, retaining the existing CD before the
first familiar callback. Engine entry never increments the menu load count. A flag20

Connected-stage candidate construction borrows the departing actual familiar owner.
Seven records and selection transfer atomically; cached overlay history/events/sound
cursor and generation serial survive, subject to original mode0 writes. Entity/row
records start empty and root/wings get real new generations. Cached deselection keeps
the loaded binding without creating a root; later menu reselection reuses it and
increments once. Failed candidate construction preserves the departing owners.
Audio is prepared for the actual destination stage; full CD bookmark/queue continuity
and general dialogue/cutscene sharing remain unfinished.

Fresh boot/Continue uses active saved card bits and default familiar records when the
legacy format supplies none. Existing v9 bytes and reserved-zero checks remain unchanged:
they still do not persist familiar records. In-memory stage handoff is separate from
ordinary save/Continue progression. Native checks cover two actual session commits
between Laboratory/Marble Gallery, all21 record words, an actual raw-reward API update,
no extra load/callback/game-clock advance, cached-none/reselection, real rendering and
candidate failure. Fresh in-memory v9 roundtrip checks use a supplied active-card/save-room
context; they establish no familiar progression persistence, acquisition or route evidence.

`SotnFairyRuntime_Clear` validates the actual4..7 identities/generations and all
three possible5..7 DD/DF leases before clearing any entity or row. Complete
namespace validation checks every actual row, including hidden sentinels, overlaps
and tagged rows absent from the supplied leases. An empty lease cannot silently
abandon an owned row. Stage/common/shared player rows retain their real owners.

Successful retirement clears only the four entity records. It preserves the overlay
binding, generation serial, history, room-event links/timers and sound cursor for a
later initialization of the same loaded overlay. Full overlay replacement remains
a separate operation. Repeated retirement is a no-op after validation. The native
update skips an empty retained namespace before querying active-card providers;
subsequent ordinary gameplay continues without inventing a familiar binding.

or retirement commits. Previously, its precheck validated only row0 of each lease.

earlier sibling's129 rows had already retired. The regression reproduces that
failure against the previous implementation and verifies that the current path
preserves the entire pool and runtime on failure. Both ordinary translation and
room retirement reject stale ownership before changing anything.
